# Справка для нейросети: как создать и добавить модуль во вспомогательный мод R.E.P.O.

Проект: `C:\Users\Kolya\Desktop\REPO-чит` (папка исторически так называется). Это вспомогательный
BepInEx-мод для игры R.E.P.O. (Unity 2022.3, Mono, Photon PUN2). Называй его «мод», не «чит-меню».
Исходники — `RepoCheatMenu/*.cs` (имена `RepoCheatMenu`, `CheatState` исторические, не переименовывать).

Есть ДВА вида модулей. Выбери нужный до начала работы:

| Вид | Что это | Где описано |
|---|---|---|
| **Скрипт-модуль** | `.csx`-файл, который игрок пишет/запускает в игре, без пересборки | `AI_SCRIPT_GUIDE.txt` |
| **Встроенный модуль** | C#-класс внутри мода: тоггл/кнопка в меню, пересборка | этот файл |

Если просят «добавить функцию в меню» — это встроенный модуль. Если «напиши скрипт для консоли» — читай
`AI_SCRIPT_GUIDE.txt`, а не этот файл.

---

## 0. Железные правила (нарушать нельзя)

1. **Ничего не выдумывай.** Любой класс, поле, метод игры сначала найди в `decompiled/` (декомпил игры,
   по файлу на класс) через grep. Нет в декомпиле — нет в коде. Память о Unity/Photon «как обычно»
   для этой версии часто неверна.
2. **Игру не запускай и не перезапускай без спроса** и не копируй сборку в профили, пока игра открыта.
   Пользователь может играть. Собирать (`dotnet build`) можно всегда.
3. **Пользователь играет гостем (не хост).** Всё, что игра защищает `MasterOnlyRPC`, ему бесполезно.
   Для каждой новой функции прямо напиши: работает у гостя / только у хоста / только локально.
4. **Не сломай существующее:** правки точечные (Edit), файлы не переписывать целиком. Окончания строк и BOM
   в файле сохраняй как были (`*.ps1` — только UTF-8 с BOM).
5. **Не клади бэктики внутри двойных кавычек в bash и не делай heredoc с python** для текста с кириллицей —
   файлы пиши инструментом Write/Edit.

## 1. Анатомия встроенного модуля (7 шагов)

Пример по ходу: тоггл `HonkStorm` («Шторм гудков») — `HonkHack.cs`. Смотри его как образец.

### Шаг 1. Найди, что именно делать в игре

```
grep -rn "HonkRPC" decompiled/        # реальный метод
```
Выясни: это `[PunRPC]`? Что за гейты внутри (`SemiFunc.MasterOnlyRPC`, `OwnerOnlyRPC`,
`MasterAndOwnerOnlyRPC`, `IsMasterClientOrSingleplayer`)? Каталог всех RPC игры и методика —
навык `repo-cheat-dev` (папка `C:\Users\Kolya\.claude\skills\repo-cheat-dev`, файлы `references/rpc-catalog.md`,
`rpc-security.md`) и `CLAUDE.md` проекта.
Если функции гейтят хостом, у гостя она не заработает — так и скажи, не обещай.

### Шаг 2. Файл `RepoCheatMenu/ИмяHack.cs`

Статический класс в `namespace RepoCheatMenu;`. Шаблон:

```csharp
using UnityEngine;

namespace RepoCheatMenu;

// Что делает, откуда это известно (файл декомпила и строка), работает ли у гостя.
internal static class ПримерHack
{
    private static float _next;

    // Вызывается по таймеру (~33 раза/с) из Patches.ApplyStats — см. шаг 4.
    public static void Apply()
    {
        if (!CheatState.ПримерВкл.Value) return;          // выключено — ничего не делаем
        if (Time.unscaledTime < _next) return;
        _next = Time.unscaledTime + Mathf.Max(0.2f, CheatState.ПримерИнтервал.Value);

        // Приватные поля игры — ТОЛЬКО через GameReflect, прямой доступ бросает FieldAccessException:
        PlayerAvatar local = PlayerTargets.Local;
        if (local == null) return;                         // не в игре
        int hp = GameReflect.Get<int>(GameReflect.Get<PlayerHealth>(local, "playerHealth"), "health");
    }

    // Кнопки меню вызывают публичные статические методы без аргументов.
    public static void ПримерДействие() { /* ... */ }
}
```

Полезные готовые вещи: `GameReflect.Get<T>/Set/Invoke` (приватные поля и методы), `PlayerTargets.Local`
(локальный игрок), `PlayerTargets.NameOf(p)`, `GameManager.Multiplayer()` (онлайн или сингл),
`Plugin.Log.LogInfo/LogWarning/LogError`, `EventLog.Write("категория", "текст")` (структурный лог в
`RepoCheatMenu_Logs/`), `DynamicIsland.Notify(заголовок, подпись, positive, isSwitch)` (уведомление).
Вызов RPC: `photonView.RPC("ИмяRPC", RpcTarget.All, аргументы)`; в синглплеере (`!GameManager.Multiplayer()`)
вместо RPC вызывай метод напрямую (`GameReflect.Invoke`).

### Шаг 3. Настройки: `CheatState.cs`

Три места, имя везде одинаковое:

1. Объявление поля (рядом с родственными):
   ```csharp
   public static ConfigEntry<bool> ПримерВкл;
   public static ConfigEntry<float> ПримерИнтервал;
   ```
2. Привязка в `CheatState.Init(ConfigFile config)` (секция — строка-группа в конфиге):
   ```csharp
   ПримерВкл = config.Bind("Raid", "ПримерВкл", false,
       "Что делает, и честно: работает ли у гостя.");
   ПримерИнтервал = config.Bind("Raid", "ПримерИнтервал", 1f,
       new ConfigDescription("Интервал, сек.", new AcceptableValueRange<float>(0.2f, 10f)));
   ```
3. Регистрация тоггла для бинда клавиши (там же, где остальные `KeybindManager.RegisterToggle`):
   ```csharp
   KeybindManager.RegisterToggle(config, "ПримерВкл", ПримерВкл);
   ```

Бесплатно получаешь: сохранение в конфиг, назначение клавиши средним кликом по строке в меню,
автоматическое выключение в «панике» (`PanicHack` обходит ВСЕ публичные `ConfigEntry<bool>` в `CheatState`),
уведомление на острове при переключении. Не-тогглы (числа, строки) паника не трогает.
Исключение из паники — только если поле добавлено в `NeverSwept` в `PanicHack.cs` (для служебных настроек).

### Шаг 4. Подключи вызов

- **Периодический код (тогглы):** в `Patches.cs`, метод `ApplyStats()`, добавь строку рядом с похожими:
  ```csharp
  RunSafe(nameof(ПримерHack), ПримерHack.Apply);
  ```
  `RunSafe` ловит исключения: один сломанный модуль не валит остальные. Каденс ≈ 33 тика/с.
- **Рисование на экране (HUD, эффекты):** не здесь. Каждый кадр рисует `HudRoot.Tick()` (`HudRoot.cs`) —
  добавь `Guard("Имя", Класс.Draw);` в нужное место порядка слоёв. HUD-карточки — `PlayerHud.cs`
  (смотри, как сделан виджет «Лут»: `Kind`, `Widgets`, `LootRows`).
- **Правка поведения самой игры (Harmony):** отдельный класс-патч, см. раздел 3.
- **Кнопка (разовое действие):** отдельного вызова не нужно, его делает меню (шаг 5).

### Шаг 5. Строки в меню — в ОБОИХ меню

В моде два меню, у них разные API. Добавляй в оба, в ту же по смыслу вкладку:

**Новое меню F6** — `CustomOverlayUI.cs`, метод `BuildXxxTab()` нужной вкладки:
```csharp
SectionHeader("Шторм гудков");
Toggle("Включить", CheatState.ПримерВкл);
FloatStepper("  -> Интервал, сек", CheatState.ПримерИнтервал, 0.2f, 10f, 0.2f);
Button("Подпись строки", "Кнопка", ПримерHack.ПримерДействие);
LiveInfo(() => "Живая строка: " + что-то);
```
Вспомогательные: `Toggle`, `Button`, `FloatStepper`, `IntStepper`, `Cycle`, `ColorCycle`, `SectionHeader`, `LiveInfo`.
Подсказка: строка с `"  -> "` в начале подписи считается настройкой предыдущего тоггла (выпадающий режим
меню группирует по этому).

**Старое меню RightShift** — `OverlayUI.cs`, внутри лямбды нужной подвкладки (`AddSubTabs`):
```csharp
AddSectionHeader("Шторм гудков");
AddToggleRow("Включить (пояснение)", CheatState.ПримерВкл);
AddFloatStepperRow("  -> Интервал, сек", CheatState.ПримерИнтервал, 0.2f, 10f, 0.2f);
AddButtonRow("Подпись", "Кнопка", ПримерHack.ПримерДействие);
```
Подписи — по-русски, коротко; в скобках можно честно написать ограничение («только хост»).

### Шаг 6. Harmony-патчи (только если нужно менять игру)

Класс в `Patches.cs`:
```csharp
[HarmonyPatch(typeof(КлассИгры), "ИмяМетода")]
internal static class ПримерPatch
{
    [HarmonyPrefix]
    private static bool Prefix(КлассИгры __instance, ref float __result, bool ___приватноеПоле)
    {
        if (!CheatState.ПримерВкл.Value) return true;      // пропустить оригинал: return false
        return true;
    }
}
```
Обязательно:
- **Обфускация.** Релизная сборка переименовывает методы, а Harmony связывает параметры по имени. Каждый НОВЫЙ
  класс-патч добавь в `tools/obfuscar.template.xml` строкой
  `<SkipType name="RepoCheatMenu.ПримерPatch" skipMethods="true" />` рядом с остальными. Забыл — в игре патч
  молча не сработает, а у `core` может не отработать `Awake`.
- **Методы `PhotonNetwork` атрибутом НЕ патчить** (тип с тяжёлой статической инициализацией, зависает вход в
  комнату). Патчь вручную и отложенно (образец: `DeferredAntiCrashInstallPatch` в `Patches.cs`).
- **Не пиши реальную позицию игрока** (`transform.position`/`rb.position`) внутри сетевой сериализации без
  зеркалирования в `rb.position` и обнуления скорости — иначе игрока физически утащит (см. `InvisiblePatch`).
- Транспилеры и корутины — читай `references/harmony-reflection.md` навыка `repo-cheat-dev`.

### Шаг 7. Сборка и проверка

```
cd RepoCheatMenu
dotnet build -c Release          # 0 Warning(s), 0 Error(s) — обязательно
```
Полная сборка пакета (поднимает версию, обфусцирует, кладёт на рабочий стол):
```
powershell -NoProfile -ExecutionPolicy Bypass -File tools\build-all.ps1
```
Ошибка сборки — полный лог в `tools\build-log.txt`, номер версии откатывается сам.

Проверка: успешная сборка доказывает только компиляцию. Эффект в игре проверяй, только если пользователь
не играет сейчас; иначе честно напиши «собрано, вживую не проверено». Лог игры:
`%LOCALAPPDATA%\RepoLauncher\profiles\<профиль>\BepInEx\LogOutput.log`.

Деплой в профили игры — только при закрытой игре (лаунчер сам подтянет пакет при запуске).

## 2. Скрипт-модуль (кратко)

Файл `.csx` в папке `RepoCheatMenu_Scripts` рядом с DLL; вкладка «Скрипты» меню. Пишется как top-level C# без
`class`/`Main`, выполняется внутри игры через Roslyn. Главное правило — **никаких пустых блокирующих циклов**:
ждать только через `await Task.Delay(...)`. Полное описание окружения, доступного API (`ScriptGlobals`) и
запретов — `AI_SCRIPT_GUIDE.txt`. Скрипт-модуль не требует пересборки и не попадает в паническую сводку тогглов.

## 3. Типичные ошибки (уже случались)

| Ошибка | Как избежать |
|---|---|
| `FieldAccessException` на приватном поле игры | всегда `GameReflect.Get/Set`, не `obj.field` |
| Патч не срабатывает в релизной сборке | класс-патч не добавлен в `obfuscar.template.xml` |
| Вход в комнату вечно «грузится» | патч на метод `PhotonNetwork` атрибутом; нужен отложенный ручной |
| RPC «работает», но ничего не происходит | у RPC гейт `MasterOnlyRPC`; гость не пройдёт; проверь тело метода в декомпиле |
| Игрока утащило в небо/под пол | запись позиции без зеркала в `rb.position` и без обнуления скорости |
| Клавиши срабатывают в браузере | клавиши мода уже требуют фокус окна игры (`Win32.GameFocused`); не читай `GetAsyncKeyState` напрямую |
| Кривая кириллица в `.ps1` | UTF-8 **с BOM** |
| `MethodInfo.Invoke` игнорирует значения по умолчанию | передавай все аргументы явно (особенно в сингл-ветке) |
| Строка меню есть только в одном меню | добавляй в оба: `CustomOverlayUI` и `OverlayUI` |
| Забыл `RegisterToggle` | у тоггла не будет назначения клавиши |

## 4. Шаблон задания для нейросети

> Прочитай `AI_MODULE_GUIDE.md` и `CLAUDE.md` (хвост). Добавь во вспомогательный мод R.E.P.O. модуль
> «<название>»: <что должен делать>. Сначала найди реальные методы в `decompiled/` и скажи, работает ли это
> у гостя. Затем: файл `<Имя>Hack.cs`, настройки в `CheatState.cs` (+ `RegisterToggle`), вызов в
> `Patches.ApplyStats`, строки в `CustomOverlayUI.cs` и `OverlayUI.cs`, `dotnet build -c Release` без
> ошибок и предупреждений, запись в `CLAUDE.md`. Игру не запускай и в профили не копируй.
> В конце перечисли изменённые файлы и честно напиши, что не проверено вживую.
